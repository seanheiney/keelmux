# Local captain ledger prerequisite

This package and the Store APIs implement deterministic local lifecycle observations, explicit directional read grants, typed source-linked reports, atomic all-source cursors, and a hard lifetime **reservation** limit. No producer, model invocation, provider tool, native request, daemon API, CLI, scheduler, remote source, terminal scraper or dispatch is supplied. This is a source prerequisite, not a complete advice captain or Bouncer MVP.

`AuthCaller` is trusted Store-only input from an authenticated local owner boundary. The current Service does not provide that boundary. Never populate it from request-body principal/role fields, expose bootstrap through a socket route, or interpret its existence as a credential. `BootstrapCaptainOwner` is an explicit empty-ledger initialization hook; migration creates empty tables and invents no roles/grants. These cooperating managed checks do not isolate another process running as the same OS user.

Every source read/publication rechecks the current principal role/revision, assignment control, exact captain execution, all explicit runner grants and current source execution generations. Readers have independent directional grants for every input; group navigation and owner control confer no source read scope. Pause/revoke denies further reads/publication. Owner control/cancellation reconstructs metadata without reading newly revoked source bytes; it can retire an exact pending reservation without refund. Stored source revalidation occurs only after fresh read authorization, or during private Store.Open integrity validation.

Assignments have immutable source scopes, audience, policy and `MaxReservations`. One pending reservation prevents overlapping cursor consumption. Every accepted reservation is counted forever, including cancellation/restart, and zero budget refuses. An exact retry returns an immutable reserve/report receipt after current authorization and full ledger/source validation; it never reserves or reports twice. A control/quiet/cancel retry returns verified current status and does not reapply its transition. Config receipts are historical acknowledgments, never renewed role or source authority.

Scans query exact local lifecycle threads with combined row/byte bounds, retain all selected row digests, and omit Detail, names, paths, terminal and account text. Quiet/unsupported checkpoints consume no reservation; unchanged scans create no journal entry. Reports are constructed internally from every meaningful source event. Coalescing groups finite category/session/operation facts while preserving every source key once. Unknown kinds become `unsupported`; their cumulative count survives quiet checkpoints. Captain reports/control are not written into watched worker streams; self captain session/thread sources refuse.

Every view declares an observed lifecycle subset, incomplete history, no native output and unknown historical execution origin. Current execution is a fence, not attribution of old events. The existing MAX+1 source sequence cannot establish unseen-tail retention or full-history completeness. Private canonical receipt chains detect missing/drifted retained rows and anchors; they are integrity checks, not signatures against same-user rewriting. Native invocation is `not_invoked`; actual provider turns/tokens/charges stay unknown. Separate source-qualified usage observations remain separate; no monetary cap is promised.

Finite limits and immutable chain/schema checks fail closed, including cumulative source/record/ledger bytes checked before retention. Reaching a lifetime bound requires an explicit future owner-reviewed repair/retention design; this increment never compacts, refunds, reuses identity or fabricates missing receipts. Model/tools integration, authenticated production caller context, scheduling, remote reporting and actual native qualification remain pending.
