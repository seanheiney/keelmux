# Local reusable capability registry

`Open(stateDir)` returns the registry without creating state. An absent library has a virtual `default` profile (name `Default`, revision 1). Reads and resolution do not create a directory, lock, catalog, daemon or identity. `Open` refuses a held writer lock after five seconds; methods respect the supplied context.

A local import reads `keelmux-plugin.json` and its exact declared file inventory. Schema 1 has lower-case portable package/component IDs, a version, optional provenance metadata, a `files` map of bundle-relative paths to SHA-256 hashes, and optional `skills`, `rules` and `tools`. A skill directory contains a declared `SKILL.md`; a rule is a declared `.md` file. The manifest does not include itself in `files`. Unknown fields, duplicate keys, JSON field case aliases, invalid UTF-8, traversal, symlinks, hardlinks, special files, undeclared files and empty extra directories are refused. Bounds are 256 KiB of manifest, 512 files, 1 MiB per asset, 16 MiB of asset bytes and 16 path components. Input files must be owned and not writable by another user. Tool environment declarations contain variable names only. HTTPS declarations refuse embedded login, query and fragment values. A declaration never executes its command, contacts its URL or certifies its publisher.

Mutation creates an owned private `stateDir/library`. Its directories are 0700; stored manifests, assets, catalog and retained lock are 0600, with no execute bits. Ancestor symlinks are refused rather than resolved. There are at most 256 retained package revisions and 64 profiles. Pack digests cover the normalized manifest and all declared file hashes; every declared byte is verified before copying and on subsequent reads. Importing an existing pin is idempotent. Importing a distinct revision never changes any selection.

Selecting a package enables all its declared components except explicit `kind/id` overrides. Turning a package off preserves its exact digest and component preferences. Selecting a different digest explicitly starts its component preferences at their defaults. Same-value toggles leave catalog/profile revisions and file bytes unchanged. Resolution verifies every stored revision, including disabled selected pins, and orders packages and components deterministically. Its digest covers only the canonical selection map, whose immutable pins cover component definitions and bytes; unrelated catalog/profile changes do not change this identity. Catalog and profile revisions remain separate observations. `loaded` is always `unknown`: a desired declaration does not prove that a native process loaded it.

Removal archives one exact intact pin under `archive/<digest>`, disables only profiles selecting that pin, and preserves their digest/component preferences and other revisions. The archive is retained; there is no purge or automatic session reconfiguration. Archived roots are not exposed by `PackageRoot`, and importing the same archived pin is refused pending an explicit future restoration operation.

A retained lock serializes cooperating processes. A durable `pending.json` binds the exact previous catalog, the intended next catalog and any exact pack movement. Directory movement and catalog publication are synced. Reads refuse pending operations without changing them. The next explicit mutation can complete an interrupted import/removal only when the current catalog is the recorded before/after state and package bytes, ownership and identities still match. Ambiguous, edited or future state stays intact for repair. Failure before a durable intent can leave unpublished private staging bytes for explicit repair; they are never exposed as an installed pack. This ownership protocol is local coordination, not a sandbox against another process with the same user's privileges.

No credential store, native configuration, login, executable, remote clone, provider or model is used by this package. Native preview/application and actual loaded/tool-health observations are separate contracts.
