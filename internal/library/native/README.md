# Explicit workspace applications

`Preview(ctx, registry, resolution, target)` reads a verified registry resolution and its exact immutable package roots. It returns generated bytes, native argv, preimages, preserved-content collisions, unsupported declarations and loading uncertainty. Preview and absent `Status`/`Recover` create no state. `Target` selects one existing owned canonical absolute workspace, harness, and application ID. Profile/application IDs use the registry identifier syntax; skill names have stricter native restrictions.

`Apply(ctx, registry, plan)` resolves and regenerates the plan before state creation and again under a retained workspace writer lock. Caller-edited plans, stale revisions, changed package bytes, foreign files and native precedence conflicts refuse. An updated resolution can reuse the same application ID. Only unchanged previously owned files are replaced or removed, so profile component toggles preserve unrelated content. Identical profile/content retries reuse the receipt.

`Status(ctx, target)` returns `ApplicationStatus`. `Verified` means the recorded workspace, lock identity, private receipt, current owned bytes and allowed argv shape agree. It does not prove publisher authenticity, account authority, sandbox isolation, native loading or invocation. A launcher must obtain a current registry resolution and preview, compare profile ID/revision/digest and desired file hashes/byte counts/argv with the receipt, and refuse collisions or required unmapped components before adopting its argv. Applying files never proves that a running process reloaded them. `Applied`, coverage, `Loaded=unknown` and `Reload=pending_or_unknown` stay separate.

`Remove(ctx, target, expectedReceiptDigest)` removes only unchanged owned files and empty directories created by the application. Existing native content is never adopted or overwritten, even when its bytes happen to match. Changed owned content refuses. No account store, permission policy or running process is changed.

The private ledger is `.keelmux-native/<application>/{receipt.json,intent.json}` inside the selected workspace. A workspace-wide 0600 lock contains its actual device/inode; receipts bind that retained identity. Existing private state requires 0700 directories, 0600 single-link regular files and the current owner. Unsafe existing modes are refused without tightening them. All path components use anchored `openat`/`NOFOLLOW`; symlinks, special files and hard links refuse. The lock is checked before and after local write/publication boundaries and is never recreated when application state exists. The writer wait is bounded to five seconds or the caller deadline.

Intent is fsynced before native files are changed. Cancellation or a failed acknowledgement can leave a pending intent, and Status never verifies it. `Recover(ctx, target)` explicitly completes only the saved local file intent whose entire preimage/afterimage set still agrees. Unknown or edited bytes stop recovery before another file effect. Recovery never resolves a new profile, launches a process, executes MCP, or replays an external provider effect. Publication uses exclusive temporary files, fsync, atomic rename and directory fsync. This serializes cooperating same-user writers; it is not security isolation from that user.

## Mapping contracts

| Harness contract inspected | Skills | Rules | MCP and launch argv |
| --- | --- | --- | --- |
| Codex CLI 0.159.0 | `.agents/skills/<name>` | Owned `AGENTS.md` | Owned `.codex/config.toml`; native `env_vars` names only |
| Claude Code 2.1.296 | `.claude/skills/<name>` | Namespaced `.claude/rules/*.md` | Owned application `mcp.json`; supplemental `--mcp-config <absolute path>`, preserving native approvals and other config |
| Gemini CLI 0.52.0 | `.gemini/skills/<name>` | Owned `GEMINI.md` | Owned `.gemini/settings.json`; environment-name placeholders and Streamable HTTP `httpUrl` |
| Grok 1.0.50 (c58f321264ba) [stable] | Immutable assets copied into the application and referenced by a generated instruction index | Generated Markdown contents as one literal `--rules` value | No qualified MCP hook; explicitly unmapped |
| OpenCode 1.18.21 | `.opencode/skills/<name>` | Owned instruction file selected by project `opencode.json` | Project `opencode.json` local/remote MCP definitions; environment-name placeholders |

Grok's index is instruction compatibility mapping, not native skill discovery. A generated owned rules file records the exact argv bytes. Its combined literal rules/index argument is limited to 32 KiB when JSON encoded, including quotes and escapes, with a secondary 64 KiB raw bound. Preview refuses overflow before native file effects, and Status enforces the same bound. This reserves room for argv and metadata under the existing 64 KiB launch transport ceiling; the launcher must also preflight its complete encoded request. Existing AGENTS.md, GEMINI.md, native project settings and skill directories are preserved as collisions with explicit manual opt-in guidance. Workspace `.agents`/Claude-compatible aliases and OpenCode's alternative project JSONC are checked rather than choosing precedence. Claude's existing project MCP names are checked against supplemental names. Parent, user, managed and environment-selected configuration is not inspected, so global precedence and loaded state remain unknown.

Mapped skill assets remain byte-identical to their immutable pins. The initial portable frontmatter subset is `name`, a one-line `description`, `license`, and `compatibility`, with a matching lower-case hyphenated name. Structured/multiline or unknown native frontmatter, including permission metadata, remains explicitly unmapped. This deliberately bounded subset avoids inventing equivalent behavior for fields with different native meanings. HTTPS environment names alone cannot determine an authentication header and remain unmapped. No environment value is read or written, no shell command is generated, and tools are never executed by this package.

Bounds are 512 source/generated files, 1 MiB per asset, 16 MiB total content, 32 relative path components and 64 MiB private intent/state. The registry is responsible for verifying its complete immutable package inventory; the mapper independently rechecks declared bytes and selected roots before applying.

## Evidence boundary

The focused suite covers source pins, all five generated mappings, absent-state reads, retries, restarts, same-ID update/toggle/removal, stale/forged plans, native/alias collisions, permissions, symlinks/FIFOs/hard links, drift, cancellation, each commit boundary, lock loss/replacement, whole-intent recovery validation and receipt-authored argv refusal. `-tags library_registry` enables an additional real registry interoperability test once that implementation is integrated. It may also run against a read-only Go overlay of the exact registry source.

These are temporary filesystem fixture proofs. Installed `--version`/`--help` probes and official documentation establish the declared mapping contract only. Actual native configuration parsing, loading, invocation, approval behavior, MCP health and live reload remain unqualified. No model turn, provider request, credential lookup, native configuration write or native process launch is part of these tests.
