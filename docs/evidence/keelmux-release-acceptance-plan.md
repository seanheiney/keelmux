# Keelmux release acceptance plan

This is an unexecuted release plan, prepared independently on 2026-10-10 from repository `8259b648d7f92c5b8c4c27c41524f23b61ac6795`. It does not certify a package, installer, platform, public release or model workflow. The provisional first-release name is Keelmux; the captain verifies that name and owns the final release contract.

Existing evidence establishes a bounded macOS arm64 terminal workflow with Codex 0.159.0 and Claude 2.1.296, and separate zero-turn Codex broker experiments. Release acceptance must exercise the final packaged binaries rather than treating those earlier source checkouts as package proof.

| Gate | Independent execution and pass condition | Evidence boundary |
| --- | --- | --- |
| Artifact identity | Record final source SHA, clean/dirty source fingerprint, archive/checksum digests, version, target OS/architecture, installer digest and every installed executable digest. The archive contains `keelmux`, `keelmuxd`, `keelmux-entry` and functioning `bp`, `bpd`, `bpg` compatibility aliases. All commands identify the same release. | Cross-compilation alone does not establish runtime support. A publicly downloadable release is a separate gate. |
| Fresh installation | Execute the documented installer against an owned loopback release fixture using a short temporary HOME, install prefix and PATH. Install without sudo and preserve preexisting user files. Inspect executable and private metadata modes. Run help/version/doctor from the installed layout. | Do not install or upgrade tmux, a vendor CLI, native authentication, shell settings or login configuration. |
| Integrity and failure | Corrupt the archive, truncate a download, omit an artifact/checksum, present unsupported OS/architecture, interrupt before activation, and make the target unwritable. Each case fails without replacing the last accepted executable tuple or leaving an active partial install. | SHA-256 matching proves integrity relative to the selected manifest; publisher authenticity needs its own release mechanism and claim. |
| Collision and repetition | Seed unowned files/symlinks with every command name; preserve them and refuse collisions. Reinstall the same owned version; run concurrent installers; upgrade a prior owned version. Observe which version becomes active and retain recoverable prior bytes where promised. | Do not infer upgrade/downgrade compatibility from atomic file replacement. |
| Installed sibling discovery | Cold-start a daemon through both `keelmux` and `bp`, outside the source checkout. Confirm the daemon is the installed matching executable and inherited helper paths reach the installed matching CLI. Exercise compatibility aliases through the native link helper. | Current entry points locate siblings relative to `os.Executable`; a CLI-only copy is insufficient. |
| State selection | A fresh default selects `~/.local/state/keelmux`. An existing validated private `~/.local/state/agent-backplane` is reused, preserving host/session/execution IDs. Explicit `--state` overrides environment; otherwise `KEELMUX_STATE_DIR` precedes `BP_STATE_DIR`. Test paths containing spaces. | A malformed, permissive or symlinked legacy authority must fail without creating a second fresh authority. Native credentials remain in their native realm. |
| Isolation and privacy | Seed native settings, login sentinels, unrelated tmux/server paths, legacy state and PATH collisions; compare bytes/modes before and after install, state startup, setup preview and uninstall. Validate private state/socket/registry/receipt modes and reject unsafe state paths. | Use owned sentinels and sockets. Do not inspect credentials or connect to existing user terminals. |
| Local two-provider workflow | With final installed binaries, separately launch actual Codex and Claude using existing authorized native logins in an already trusted owned repository. Correlate exact inherited launch/link identity; select each actual native terminal in the TUI; observe composer before unsubmitted Unicode, Escape and resize; detach with Ctrl-G d and reconnect to the same execution/PID/start/pane. | Native launch/link-before-exec does not prove skill invocation, effective model/account or a completed model turn. Do not submit Enter/model prompts during this bounded gate. |
| Recovery and arbitration | Restart TUI and daemon with both native processes alive; compare exact durable identities and runtime locators, reject duplicate launches, preserve selection/group/local draft. Separately lose the owned tmux runtime and report missing execution. Drop completed launch/attach/stop acknowledgements, retry original operation, and test competing writers, read-only attachments and forged releases. | Ctrl-C may legitimately exit a vendor CLI; test interrupt separately from uninterrupted recovery. Host reboot/native continuation are separate gates. |
| Entry scope | If the release advertises the private entry, rerun scoped inventory/attach/detach and adverse restart/revocation/home-loss gates using packaged entry/home/client binaries. | Two logical homes on one computer do not prove enrollment, authenticated SSH transport or two physical servers. |
| Owned skills | Preview causes no writes. Installation refuses unowned collisions. Existing owned `backplane` bundles/ledger identity remain compatible; project/user removal retains the matching bytes and receipt in the private archive. Native discovery and execution are distinct. | Do not rename/adopt an existing unowned bundle or claim loaded/invoked instructions from file installation or menu discovery. |
| Upgrade with durable work | Keep owned native panes alive, upgrade the executable tuple, and reconnect after an explicit supported daemon transition. Preserve registry/journal/lease/operation IDs and report compatibility refusal clearly. | A downgrade requires a tested schema/version policy; do not silently open an incompatible registry. |
| Uninstall and reinstall | Uninstall only a matching owned install. Preserve user state, native settings/login, retained skills archives, unowned PATH collisions and existing native panes unless a separately documented explicit lifecycle action was requested. Reinstall and recover the retained registry where supported. | Removing binaries can make future helper calls unavailable until reinstall; document the actual behavior. Never kill by a saved PID alone or delete native state. |
| Documentation | Execute every first-run command from a clean installed layout. Check names, aliases, state precedence, prerequisites, keyboard actions, install/uninstall/upgrade behavior, recovery limits and troubleshooting against actual output. | Keep experimental broker features, model work, account/model attribution, approval routing, pagination, remote hosts, continuity and chat claims tied to their own evidence. |
| Public distribution | After captain publication, independently download the exact public release artifact through the documented one-line installer and verify the published digest/version and first-run journey in a disposable environment. | Local loopback fixtures and a private Git push do not prove public GitHub delivery. |

The installer contract is now fixed: POSIX `install.sh` accepts `--version vX.Y.Z`, `--prefix ABS`, `--bin-dir ABS`, `--uninstall` and `--help`. `KEELMUX_DOWNLOAD_BASE_URL/vX.Y.Z/` selects the asset fixture; plain HTTP is restricted to localhost with explicit `KEELMUX_ALLOW_TEST_HTTP=1`. `KEELMUX_INSTALL_DIR` and `KEELMUX_BIN_DIR` select the owned code and command locations. Archives contain the canonical tuple, three relative aliases, LICENSE, README.md and RELEASE.json. The manifest pins version, full source commit, target and per-file digests. The independent harness uses Python standard-library HTTP fixtures and private temporary directories, never the real user's installation. Installer and product source remain captain/worker-owned.

The plan was followed by an [independent macOS package run](keelmux-release-macos-independent.md): all 16 executed groups passed against clean archive source `0be153b2ae2fc2ad0d47120287bcdce2f8f3cc44`. Its optional `--runtime` path started only empty owned packaged daemons and proved private Unix peer/process identity before cleanup. It did not start vendor CLIs. The receipt explicitly lists remaining native, recovery, public-delivery and compatibility gates; table entries above remain requirements until their own execution is recorded.

Before public product claims, resolve the release scope explicitly. The current zero-turn broker helper does not establish a production app-server launcher, authenticated turn, nonempty or paginated history, callback/approval delivery, restart recovery, native writer handover or remote-host operation. Those remain actionable product gates if advertised by the release.
