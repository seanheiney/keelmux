# Native boot identity incident and owned cleanup

Publication is held pending repair and new exact-package qualification. This report records a failed real product gate; successful neighboring gates do not resolve the defect.

On clean `bef8ea5e9b6383bd2a7a95479c31919daff4d6e0`, the actual native three-thread/two-project IRC journey reached explicit Ergo replacement. The original live execution retained boot timestamp `darwin:1791497239:636714`; the kernel subsequently reported `darwin:1791497239:730048`, a 93,334 μs change within the same boot session. Original child and helper process-start identities still matched. Four directly authenticated private helpers reported `Alive=true`, while the frozen native backend returned `Alive=false,nil` before authentication. Managed IRC therefore persisted `stopped` without stopping the original Ergo, and replacement exited with its owned database lock still held.

Apple's [kernel clock implementation](https://github.com/apple/darwin-xnu/blob/main/osfmk/kern/clock.c) adjusts the boot timestamp when the calendar changes. Its [sysctl implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c) separately exposes the read-only `kern.bootsessionuuid`. The repair must use a validated stable boot-session identity and treat unsupported historical timestamp identities as unavailable, including lifecycle journals previously marked stopped. It must not rewrite receipts, replay launch operations or infer death from an untrusted identity.

The failed product receipt was preserved byte-for-byte with SHA-256 `81ce54095f44a3de211faabd740429fc7f7ad9a11e135bcc985b6d39ed7b5003`. A private diagnostic overlay bypassed only the defective timestamp check for cleanup, after exact peer UID/PID/start, full runtime reference and private token verification. The unchanged authenticated helper stop protocol retired four live original child/helper pairs; the failed replacement had already exited. All five recorded child/helper lifetimes were absent, the exact additional diagnostic control daemon was shut down through its authenticated instance API, and both control/native sockets were absent. No saved-PID signals, lock removal, launch replay, native input, provider/model activity, manual receipt modification or production-state change occurred. Private failed state remains retained.
