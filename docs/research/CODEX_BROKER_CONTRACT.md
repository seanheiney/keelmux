# Local Codex broker contract proposal

2026-10-10 · [tracking issue #12](https://github.com/seanheiney/agent-backplane/issues/12)

**Decision:** the first runnable target is a private local broker for the real installed Codex 0.159.0 native CLI, zero-turn bootstrap/resume of one exact authoritative thread, and a typed scoped observer. `internal/codexbroker/contracts.go` defines proposed boundaries only. It implements no policy, durable actor, native lifecycle or semantic delivery. Existing terminal capability flags stay unchanged. No remote-machine, authenticated-turn or model-work claim follows from these interfaces or byte transport.

## Authority and identities

The existing `store.grants` table and `one_writer` constraint are the single cooperating writer authority. Extend that same grant with trusted principal, native/semantic kind, monotonic writer epoch and admission state; preserve the exact acquisition/client/token/execution-generation identity. `Grant` in this proposal is a view of that row, never a second broker lease. A fenced grant retains the active writer slot while sends, callbacks or uncertain effects remain unresolved. Read-only rows do not own the slot. Only a verified safe handover atomically retires the old row and installs the next epoch.

Bind every connection permanently to its original trusted principal, client, connection incarnation, acquisition operation, writer epoch, product host/session/execution generation, app-server incarnation with PID/boot/start evidence, and exact native thread. Native clientInfo, request IDs and socket paths do not authenticate identity. An owned spawner must prove a private per-launch endpoint/capability and process binding before `Bind` accepts it; peer/process checks still require macOS/Linux proof. Keep tokens, capabilities, auth data, home/upstream paths and server/install identifiers out of inventory and chat.

Old native connections/endpoints never regain write authority after revoke or handover, even for the same principal. Returning native control starts a **fresh native process and endpoint** that resumes the same authoritative thread. Its old unsent draft is not replayed. A dedicated native upstream channel and a broker anchor survive disposable native UI detach so caller closure does not silently cancel authoritative work.

## Admission, receipts and callbacks

One common store/Service actor serializes all native and typed mutations with release, revoke and handover. It validates policy and the original binding against the live grant, persists the intent/hash and `Attempted` **before any upstream write**, then holds the common gate through one bounded frame write. Do not hold a DB transaction over IO or wait for acknowledgement/model completion inside the gate. Queued forwarding must revalidate at this gate; sampling a lease in an unrelated worker is insufficient. Transport `Write` success yields `PendingAck`; a native turn acknowledgement yields `Acknowledged`, which does not establish model acceptance or completion.

An identical BP operation, original provenance and canonical semantic-target/payload hash returns the stored known/pending receipt. A different binding or hash conflicts. A decision hash includes the exact callback key; only transport correlation IDs are excluded. Persist the actual upstream request ID, channel and app-server incarnation before write, retaining the client-facing ID separately; remapping or reuse must never let a late response satisfy another request. Persist the generated turn/start clientUserMessageId before send; it is correlation evidence, not proven native idempotency. Any partial write, lost response, crash after Attempted or unknown effect remains `outcome_uncertain`, without replay. Reconcile only with unique exact-thread turn/item and user-message clientId/payload evidence. Absence or ambiguity leaves repair pending. On restart, attempted sends and stale endpoint incarnations stay fenced.

Callback identity includes original upstream channel, native JSON-RPC request ID (with string/number type preserved), thread, turn, item and optional approval ID, plus the original intent and full connection/writer epoch. Persist payload/hash before display; unattributed callbacks are non-actionable. Decide only through a persisted typed decision operation, exact display recipient, live original epoch and actual availableDecisions. Preserve the exact offered native action and scope: decline and cancel cannot collapse into one rejection, and unsupported choices visibly refuse. Session-wide acceptance and policy amendments are denied. Raw JSON-RPC results cannot bypass this gate. Unknown callback types require visible repair; no automatic approval. A reused request ID on another channel is distinct. An old persisted callback after upstream restart requires exact live reissue/correlation before responding. `ServerRequestResolved` settles only its exact record.

`Settle` takes evidence from the trusted owned upstream/reconciler, never a client-supplied receipt. It must validate the original stored binding, operation/hash, channel/request and native IDs. Historical settlement may record an old operation after execution generation changes without applying a current-owner or execution projection; current `Store.Resolve` alone does not provide that path.

Safe handover requires resolved sends, idle exact thread, no admitted/queued/outstanding mutations, callbacks or active turns, observed empty native queue/background terminals, and detached native writable clients. Native reader callback registration participates in the common gate and must be processed before quiescence is committed. The actor's own durable state and authoritative `thread/queue/list` plus `thread/backgroundTerminals/list` evidence must agree. Unknown/unavailable evidence blocks handover. Forced revoke fences immediately but retains pending effects/slot for repair; it does not manufacture a safe replacement grant.

## Default-deny wire policy

Decode the installed wire with jsonrpc either absent or exactly `2.0`; reject batches, duplicate keys, malformed/oversized envelopes, unsupported fields and unsolicited response envelopes. Validate full installed schemas, method, role and parameters. Native-local bootstrap is a separate narrow allowance from semantic observation:

| Surface | Initial contract |
| --- | --- |
| initialize / initialized | Once, bounded reviewed capabilities/version; display metadata grants no identity. |
| thread/resume | Once for a fresh valid native writer; exact thread and reviewed launch baseline, no history/path replacement or unreviewed workspace/model/policy/instruction/config overrides. Denied after demotion. |
| account/read | Native-local bootstrap `{}` or refreshToken=false only; refreshToken=true mutates auth and is denied. No semantic account/config passthrough. |
| native config/read and bootstrap lists | Pin reviewed parameters, including observed includeLayers=true; schema-aware response filtering and native compatibility must be proved. Never blanket-allow extensible config keys. |
| thread/list / loaded/list | Prefer broker-scoped inventory and opaque scoped cursor; upstream thread/list requires useStateDbOnly=true **and** filtering of globally scoped results/cursors. |
| thread/read / turns/list / items/list / goal/get | Exact granted thread/turn/item/cursor and bounds; metadata first. Typed observers receive only the typed scoped projection. |
| thread/unsubscribe | Local viewer bookkeeping; never unload the authoritative anchor. |
| Everything else | Deny until separately reviewed and tested; read-looking names do not establish safety. |

The real native resume sends config with features.plugins=false, features.apps=false and web_search='cached'. Pin those exact reviewed defaults in the baseline; allowing arbitrary resume config is unsafe and rejecting all config breaks observed native startup. Suppress/redact `remoteControl/status/changed`, which can carry global server/install identifiers. Filter every native notification by permitted thread/turn scope, withhold unknown/unscoped events, and recheck live scope before output. A configured model name is not per-turn execution telemetry.

Later, separately authorized work may add bounded-text turn/start only while idle, exact-turn interrupt as its own durable intent, and tested typed command/file-change/user-input callbacks. Active turn/start can steer, so reject it initially. Defer steer, queues/goals writes, reviews, realtime, filesystem/command/process operations, config/auth writes or refresh, plugins/MCP/billing/uploads and other input forms. Never substitute terminal send-keys for denied semantic RPCs.

## Actual integration prerequisites and gates

Current `Service.Release` checks tmux writable clients; a semantic writer may have none. Current execution reconciliation follows tmux survival, and completed stop clears all grants. Introduce distinct persistent app-server execution and disposable native projection lifecycle before wiring these contracts: projection exit/replacement cannot stop the authoritative conversation, retire a semantic grant or accidentally advance its generation. Extend the common release/reconciliation/stop paths and durable receipt settlement; a broker mutex beside the existing authority is insufficient. A store migration must preserve legacy lease/token/operation bytes and native-only provenance, without inventing a trusted principal or enabling semantic authority for legacy rows.

After captain approval/publication, implementation gates are: deterministic fake-upstream admission/revoke/crash/partial-write/lost-ack races; exact old-epoch and same-principal reconnect rejection; callback channel/ID reuse and delayed decisions; malformed/default-deny policy and global list/event leak tests; app-server versus projection lifecycle and unknown quiescence blockers. Then reproduce the real installed native zero-turn bootstrap/resume through the private broker, with zero RPC policy errors, zero model turns, exact thread durability and scoped typed observation. Native disconnect/reconnect and filtered-response compatibility remain gates.

Real prompts, real approval routing, semantic/native turn handover, nonempty lost-ack correlation and model/account/usage attribution require separately authorized real-turn proof. None was performed for this contract. Source compile/format checks can validate these declarations only. The private local wire transport is a dependency, not evidence that the policy/authority or runtime adapter exists.
